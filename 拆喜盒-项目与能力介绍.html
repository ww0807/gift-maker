拆喜盒
AI 驱动的个性化纸艺礼物制作工具

将四张人物照片转化为风格统一的 Q 版形象，并完成可编辑包装盒设计与 A3 印刷文件交付。

项目角色产品设计 · 前端 · 后端集成 · 部署
技术关键词React · TypeScript · SVG · Seedream · veFaaS · TOS

项目概述

拆喜盒解决“为重要的人做一份有记忆点的实体礼物”这一创作门槛：用户不需要懂绘图或包装设计，只要上传四张照片，即可获得一组统一角色形象和一套可直接印刷、裁切、折叠的定制纸艺礼物。

4张人物照片转化为一套角色素材
4份独立 A3 包装盒展开图
2个云端函数承接 Web 与长耗时任务
核心难点 同时解决消费级创作体验与生产级交付问题：前端要易用、可自由编辑；后端要稳定处理生成与图像分割；导出结果还必须满足纸艺包装的实际印刷尺寸与折叠结构。

我完成的端到端链路

素材上传四图预览、批量替换、浏览器端设备识别与邀请链接访问。
AI 形象生成将四张参考图合成统一风格的 2×2 角色板，再进行背景移除与四图拆分。
可视化排版对文字、配色、主题、装饰和人物位置进行实时编辑、撤销重做与自动保存。
印刷交付生成四页横向 A3 矢量 PDF，保留裁切、折线和粘贴结构，支持线下成型。

能力一：产品与交互设计

我把复杂的创作流程拆成“上传 → Q版形象 → 排版预览”三步，让用户始终知道当前状态、下一步和可回退路径。编辑工作台将高频操作集中在左侧，而把包装效果作为中心视觉焦点。

能力二：复杂前端编辑器与印刷输出

工作台不是静态预览，而是一套基于 React、TypeScript、Zustand 和 SVG 的编辑系统。包装盒的四个可编辑面、人物的移动/缩放/旋转、素材层级、文本字体与颜色都可实时更新，并同步映射到实际展开图。

SVG / INTERACTION

把包装结构转为可编辑坐标系统

基于固定纸张规格和面板边界定义包装展开图，使用户元素能以统一坐标、缩放和旋转规则落入对应区域。

PDF / PRINT

从编辑画布到印刷交付

使用 jsPDF 与 svg2pdf 输出横向 A3；在导出前将字体转为路径，避免印刷环境缺字或字体替换。

能力三：AI 图像工作流与云端架构

我将生成链路设计成异步任务，避免 Web 请求被模型调用和图像处理阻塞。Web 函数负责权限、任务创建、预签名上传与状态查询；生成函数负责模型调用、抠图、透明 PNG 校验和四宫格拆分。

工程化处理要点
  • 生成阶段以 UPLOADING → GENERATING → READY_FOR_REVIEW / FAILED 状态机对前端暴露进度和失败信息。
  • 先生成一张严格 2×2 的角色板，再统一抠图、按格切分，保证四个人物的风格和透明背景处理一致。
  • 为 Linux Native 运行时打包匹配的 sharp 依赖及 Node 二进制，规避本机 macOS 构建产物无法直接在函数环境运行的问题。
  • 通过预签名 URL 直传图片，减少应用服务器中转；邀请码、设备 ID 与每日额度共同约束访问与使用频次。
